# Nemoterm i18n 设计与中文译稿

状态：设计和词表草稿，**尚未接入可执行文件**。基于 `8f663ca` 所在开发分支的界面调查；现有 `1f4db22` 试用版仍使用英文界面。

## 首版行为

新增独立的“窗口 → 界面语言”页面，提供“跟随 Windows 显示语言 / English / 简体中文”。首版选择保存后重启 Nemoterm 生效；Cancel 不保存。它是全局外观偏好，不随当前 profile 切换。中文采用简体，繁体可使用同一机制另加词表，不能以简繁字符转换代替术语审校。

语言只影响 Nemoterm 自己的菜单、设置、提示和错误说明。Shell、应用输出、终端字符编码、输入法、子进程环境和自动化协议均保持各自的原有语义。现有 `Window / Translation` 管的是字符编码，中文应为“字符编码”；界面语言使用新的独立页面。

保留单 EXE 分发。中英文词表在构建时生成只读 C 数据并链接进程序；运行时不加载 JSON、不增加 DLL、翻译框架或字体文件。英文作为缺失条目的回退语言。内存成本必须测量，不能仅以词表文件大小推算私有工作集。

## 已找到的接入点

| 位置 | 当前行为 | 接入工作 |
| --- | --- | --- |
| `vendor/putty-0.85/config.c` | 平台通用设置标签、说明、选项及动态 profile 文字 | 按语义 ID 查表；动态文字先选模板，再填参数 |
| `vendor/putty-0.85/windows/config.c` | Shell 列表、Windows 键盘、声音及字体选项 | 翻译程序文案，保留 Shell 名称、实际路径和用户内容 |
| `vendor/putty-0.85/windows/controls.c` | 控件创建、列表文字、快捷字母和自动换行 | 使用明确的 Unicode 显示接口；用字符而不是字节测量与换行 |
| `vendor/putty-0.85/windows/dialog.c` | 分类树、设置标题、About、Licence、Event Log | 显示标签与内部分类路径分开；标题支持 Unicode |
| `vendor/putty-0.85/windows/window.c`、`nemo_tabs_host.inc` | 终端上下文菜单、标签相关命令与关闭确认 | 命令 ID 不变，仅替换显示文字；保持模态与焦点约束 |
| `vendor/putty-0.85/windows/utils/message_box.c`、`shinydialogbox.c` | 提示窗口与模态包装 | 查表后调用宽字符接口；沿用已有嵌套弹窗状态管理 |
| `vendor/putty-0.85/windows/storage.c` | profile 注册表存储 | 全局语言使用独立根级值，不写入各 profile |

不能直接把英文常量换成 UTF-8 中文。`controls.c` 目前的 `staticwrap` 用 `strlen` 和窄字符文字测量，`shortcut_escape` 按字节寻找快捷字母，部分窗口与列表 API 也仍是 ANSI 路径。即使中文 Windows 恰好显示正确，在英文 Windows 上也不可靠。应明确使用 `CreateWindowExW`、`SetWindowTextW`、宽字符列表/树消息等接口；在边界进行一次受控转换。Windows 的 A/W 两套接口及 UTF-16 约定见 [Microsoft 字符串文档](https://learn.microsoft.com/en-us/windows/win32/learnwin32/working-with-strings)。

## 资源与接口约定

译稿为 [英文基准](../locales/en.json) 和 [简体中文](../locales/zh-CN.json)，当前各 **289 条**。覆盖主要菜单、分类树、profile、Shell、响铃、快捷键及常用终端/窗口设置。这是第一批译稿，**不表示全部运行时文案覆盖**；动态字体描述、完整下拉选项、剩余说明与错误分支还需随接入补齐。新语言页的文字属于设计新增条目。

- 使用稳定语义 ID，例如 `bell.overload.enable`。显示文字相同但语境不同，可以保留不同 ID。英文修改不应改变 ID。
- JSON 使用 UTF-8，构建工具将字符串转成确定的 C 字符串/UTF-16 数据，生成文件不依赖开发机代码页。先完成取词接口，再按界面替换调用点；不在运行时遍历窗口做“英文字符串替换”。
- 推荐普通文字 API 为 `nemo_ui_text(id)`，返回只读字符串；参数模板使用受限的 `nemo_ui_format(id, args)`，返回由调用者释放的结果。具体命名可随实现调整。
- 动态参数使用 `{app}`、`{profile}`、`{shell}` 等命名占位符，允许译文调整语序。生成器检查两个语言的参数集合一致，拒绝未声明参数、未知格式说明和递归展开。不要把译文直接当成任意 `printf` 格式串。
- 不翻译 registry key、命令 ID、分类内部路径、协议字段、shell ID 或用户填写的名字。`Default` 继续作为原有身份存储，仅可显示为“Default（默认）”，不能创建一个名为“默认”的新 profile。
- 已有菜单 `&` 访问键保留为“复制(&C)”；设置控件继续保留原有快捷字母元数据，中文显示时加 `(&X)`。不要重复转义 `&`，也不要从汉字的 UTF-8 字节推导快捷键。
- 当前参数模板只有命名替换需求。若以后加入有复数变化的语言，再明确扩展 plural schema；不依靠拼接词语处理数量。
- 技术标识 `Ctrl`、`AltGr`、`GDI`、`DirectX`、`OpenGL`、`OSC 52`、Shell 名称和协议序列保留原文。许可证原文保留，界面入口可以翻译。

## 语言选择与保存

建议根级注册表值 `HKCU\Software\Nemo\Nemoterm\UILanguage` 存储 `system`、`en` 或 `zh-CN`，缺省为 `system`。它与已有 `Sessions` 子树并列。保存失败时显示错误，不假装设置已持久化；取消编辑不写注册表。

`system` 使用 [GetUserPreferredUILanguages](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getuserpreferreduilanguages) 获取用户的有序显示语言偏好，从中选择支持的语言。明确匹配简体中文及其合理别名（如 `zh-Hans`、`zh-CN`、`zh-SG`）；繁体语言不静默冒充简体。支持的偏好均未匹配时回退英文。不要依据键盘布局、当前输入法或区域日期格式推断界面语言。

可增加 `--ui-language en|zh-CN|system` 作为本次启动覆盖，用于自动化与临时切换，不自动写入注册表。必须与 `-e` 的参数边界一起测试。自动化 JSON 字段始终保持固定协议名称；可增加单独的 UI language 元数据，但不翻译字段名。

当前运行进程保持启动时选定的语言；在设置中修改后，下次启动采用新值。首版不热重建所有窗口、菜单和未关闭的嵌套弹窗。Windows 自带文件/字体/颜色选择器的系统文字取决于 Windows 的语言资源，不能承诺仅靠应用词表全部改变。

## 实施顺序与验收

1. 添加嵌入式词表生成器、语言选择和英文回退；检查 schema、重复 ID、参数以及失效条目。词表完成接入后才移除 `draft-not-integrated` 状态。
2. 改造控件与菜单的 Unicode 显示边界，保持用户内容原样；完成 profile、Shell、Bell、Bindings、Tabs 和主菜单，再覆盖其余设置与错误分支。
3. 接入全局语言设置、保存/取消和启动覆盖。现有英文 UI 测试显式固定 English；新增中文 UI 测试按控件/命令 ID 操作，独立核对真实中文显示。
4. 在英文 Windows CI 上验证中文，不以中文系统代码页掩盖错误。检查中文 profile 名、包含中文的目录、下拉框、动态错误参数和重启持久化；确保用户文字没有被误当成待翻译文案。
5. 对 Profile、Shell、Bell/Overload、Bindings、Tabs、About 和确认框保留截图，检查 100% / 150% / 200% DPI 下的控件边界、汉字字形、换行与按钮遮挡。中英文都需通过 Esc、快捷键、键盘导航和模态焦点回归。
6. 对缺失翻译、未知语言、损坏设置、取消保存分别测试英文回退或保留原配置。检测新增未接入的界面文案，不能把“词表键数相同”当成“界面翻译完整”。
7. 在最终单 EXE 上确认无附带语言包，重测 GDI 启动与既有密集负载的私有/总工作集，不改变原内存验收口径。

当前交付为可审阅设计与配对译稿，没有更改应用行为，也没有运行本机 GUI 测试。
