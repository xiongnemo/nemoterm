# 改变窗口高度后的 Shift 选区

在应用已启用鼠标按钮跟踪（1002、1006）的情况下，用实际 Shift 拖选，然后只改变宿主窗口的高度。用系统剪贴板变化和应用收到的原始字节分别判断右键归属；逐格比较窗口画面，同时按 Ctrl+Shift+C 读取文本。两种渲染器都使用 SarasaTermSC Nerd Light。

| 旧版 `cf091974`，每种渲染器各执行一次 | GDI 和 DirectX 的实际结果 |
| --- | --- |
| 主屏缩短两行，文字原地保留 | 高亮消失；快捷键仍复制 `BCD`，右键落入应用 |
| 主屏缩短两行，选中的文字上移两行 | 同上，鼠标报告中的行号也随点击位置改变 |
| 备用屏按住 Shift+Ctrl+左键，只长高一行，松开修饰键后继续矩形拖选 | 预期两行 `BCD`、`bcd`；实际无高亮，快捷键复制了上一次的 `BCD`，右键落入应用 |
| 备用屏按下的行被裁掉 | 没有新高亮，后续右键由应用接收；此项通过 |

[GitHub 的原始失败运行](https://github.com/xiongnemo/nemoterm/actions/runs/44594744058)保留为失败。八个场景中两个裁掉源行的对照通过，其余六个未通过。[两份未经修改的 Actions 制品](selection-height-before-cf091974.zip)包含实际窗口、原始输入字节、剪贴板、测试进程退出状态和 EXE 身份。快捷键能复制缓存内容，不能单凭复制成功判断选区仍在。

**修复后：8/8 通过。** [候选 `6072ebc9` 的远程测试](https://github.com/xiongnemo/nemoterm/actions/runs/44595195309)使用相同脚本、字体和交互辅助程序；两个测试目录的文件清单中只有 `dist/nemoterm.exe` 的字节改变。GDI 和 DirectX 都保留了主屏上原地不动的选区和随文字上移的选区，两次均高亮三个格，快捷键和右键均复制 `BCD`。备用屏长高后，继续矩形拖动得到两行六格，两种复制动作都得到 `BCD\r\nbcd`。若按下的源行已被裁掉，没有新高亮、没有孤立的拖动输入，下一次右键正常交给应用。每种后端四例，全组选区测试六项通过。

[候选的原始记录](selection-height-after-6072ebc9.zip)包括窗口观测、前后逐项对照、构建清单、REA 静态导入表，以及独立 agent 组的原始回执。候选 EXE 的 SHA-256 是 `375390d0c4fbc1acdd2e60fca087800b46a97f1898a4105aeb1155bd4265ad1c`。同一轮中，Codex 未等待就绪的窗口接口 `Ctrl+V` 未出现附件；就绪后的两种快捷键，无论通过窗口接口还是系统键盘，都提交了正确图片。早发键失败保留在原作业，选区结果不改变其判定。
