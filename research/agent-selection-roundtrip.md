# Real agent selection and paste on the single executable

The Windows-hosted runs below use the single executable from [44131192187](https://github.com/xiongnemo/nemoterm/actions/runs/44131192187), source `d817161f32a3ef0699927da1c0739764dcd5c3dd`, 4,853,248 bytes, SHA-256 `34ae5cc92ab681e253955435b462f04b8b7c66db87b2c3f49bdc7debe55bf2a6`. The installed `SarasaTermSC Nerd Light` font file has SHA-256 `257913e04fe01695a6672feee02f7e0d7417d793ac9c3f760f5b9bb542bc3449`. The runner checked the resolved Windows family as well as the file identity.

| Operation | What the runner observed |
| --- | --- |
| Shift+drag → Ctrl+Shift+C → Ctrl+Shift+V in the real Codex TUI | A GDI tab displayed a streamed loopback response containing Chinese text, a combining acute accent and BMP and supplementary private-use icons. The fixture replaced the clipboard with a sentinel **before** pressing Copy; after Copy it left the clipboard untouched. A distinct composer prefix made the pasted prompt distinguishable from scrollback. The loopback server received the prefix followed by the selected text as an exact Unicode string. The client was `codex-cli 0.167.0`; no live model or tool calls were used. |
| Image paste in real Codex and OpenCode | Both Ctrl+V and Ctrl+Shift+V attached the generated image. The loopback requests decoded to the expected pixels, and all four jobs terminated naturally. |
| Default right click, including when the application tracks the mouse | Copied the local text. Two ordered status replies bracketed the child input stream; no pasted payload or mouse click reached the child. Sixteen rectangle cases per renderer also checked the exact selected cells and Unicode text on actual GDI and DirectX. |
| Saved right click **copy and paste** | With drag reporting and bracketed paste active on the alternate screen, Shift+drag selected `A中éZ`. The clipboard contained exactly that string. Between the status replies the child received exactly `ESC [ 200 ~` + its UTF-8 bytes + `ESC [ 201 ~`, with no duplicate bytes or forwarded mouse event. |

In 83 samples of the **frontend** after Codex startup, during streamed output and 32 resizes, private working set peaked at 6,893,568 bytes, total working set at 36,667,392 and private commit at 9,117,696. The sampler stopped before keyboard instrumentation. These are GDI scenario measurements; shell/agent processes are separate. The [full-grid stress workloads](interaction-d817161.md) have their own acceptance record.

The real client and image observations are from [44219449176](https://github.com/xiongnemo/nemoterm/actions/runs/44219449176), fixture `b0122f1`, agents artifact `14389239096`. That run's first opt-in right-click case failed (selection artifact `14390171201`): the script started three rapid gestures at the same cell, producing a triple-click line selection. The original child stream contains both delimiter characters and the line break. Fixture `d20779a` starts the independent drag on a different row. [Replay 44219944719](https://github.com/xiongnemo/nemoterm/actions/runs/44219944719) passes all three selection cases on the unchanged EXE (artifact `14390032602`). No selection implementation or expected string was changed to obtain the pass. These tests use native input messages directed to owned windows; they do not certify physical devices.
