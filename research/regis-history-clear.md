# Clearing saved terminal graphics

A ReGIS drawing that had scrolled above the top of the main screen could reappear after **Erase Saved Lines** (`CSI 3 J`). Text and ordinary raster images already discarded saved content. ReGIS views used a different representation; their decoder kept the old pixel rows even after the shared history list was cleared.

[The reproduction](https://github.com/xiongnemo/nemoterm/actions/runs/44222216582) uses the unchanged `d817161` executable (SHA-256 `34ae5cc92ab681e253955435b462f04b8b7c66db87b2c3f49bdc7debe55bf2a6`) and fixture `677282c`. It draws two distinct 101-pixel lines, scrolls three rows up, clears history, then scrolls back down. The region should contain just the line that stayed on-screen. All four jobs instead counted **202 green pixels**; the first 40 checks passed, check 41 failed. The alternate-screen case was not reached on this build.

`64c6f69` erases only the part of each main-screen graphic above row zero, including when the command is sent from the alternate screen. It frees fully discarded tile rows, clears the relevant scanlines in a partly visible tile and clips the implicit background without allocating a raster to represent empty space. The graphic identity, live rows, alternate page and parser context remain usable. The existing option to disallow remote scrollback clearing is respected.

[The fixed single executable](https://github.com/xiongnemo/nemoterm/actions/runs/44222696083) is **4,853,760 bytes**, SHA-256 `4110eae95bc4ef40dea459a7248c36ee4334c516914477fe5cf8612b9d293b0e`; source-host artifact `14391159169`. All 49 native checks passed on actual GDI, DirectX and directly presented GDI. The OpenGL request fell back to GDI. The new cases cover clearing from either screen, reverse scrolling and a subsequent repaint. Every observed job exited naturally. In the [separate component run](https://github.com/xiongnemo/nemoterm/actions/runs/44222695742), GCC/Clang sanitizers and MSVC passed the new checks for a partially clipped tile, untouched uniform background below the boundary, released allocations, screen isolation and the remote-clear preference. The original 131-frame comparison still has 10 different historical frames on each compiler, both whole and bytewise. This scrollback fix does not change those expectations.
