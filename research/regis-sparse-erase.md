# 擦掉主屏上的 ReGIS 图，不应丢掉另一屏的图

在备用屏上画一条 101 像素的红线，回到主屏，画一张 320×8192 的图。先往返切屏，确认红线、绿线都能恢复。随后在主屏上逐行擦除、向前滚动，直到 35 个屏幕高度的内容全部清完。两版程序使用相同的 SarasaTermSC Nerd Light、40×12 网格（实际每格 8×20 像素）、输入字节和检查区域。没有在切回后重画红线。

| 实际窗口 | 擦除前切回：红像素 | 擦除后切回：红像素 | 强制重绘后 |
| --- | ---: | ---: | ---: |
| 旧版 `a96e10b4`，GDI / DirectX | 都是 101 | 都是 0 | 前一步已失败，未采集 |
| 新版 `d7db3abf`，GDI / DirectX | 都是 101 | 都是 101 | 都是 101 |

[旧版的原始失败](https://github.com/xiongnemo/nemoterm/actions/runs/44668968612)及[加入擦除前切屏对照后的同一 EXE](https://github.com/xiongnemo/nemoterm/actions/runs/44669361043)都保留了擦除后实际捕获的全黑区域。新版在[托管 Windows 作业](https://github.com/xiongnemo/nemoterm/actions/runs/44669471663/job/136068351823)两种渲染器各通过 13 个阶段，所有状态回复均正确，两个进程正常退出。

旧版用一块块像素内存去表示纯色背景上新擦出的透明区域；到达图形预算后，解码器会重置，其他页面也随之消失。新版用一道行边界记录从页顶开始已经擦掉的完整区域，释放不再需要的像素块。部分擦除保留旁边的像素，在透明区域重新落笔后仍可再次擦除。4 MiB 的图形预算没有增加。

另用真实终端解析器执行 `CSI 2 J` 清除一张 2048×1152 的整页，检查最后一个像素、另一屏的红线、视口外的墨迹以及新画进已清区域的线条。GCC、Clang 记录的解码器占用从 70,088 降至 61,304 字节；MSVC 为 70,152 降至 61,368 字节。这是**解码器的分配量**，不是 Windows 进程工作集。

[原始证据包](regis-sparse-erase.zip)保留 CI 原样上传的三个窗口制品（含实际截图），以及三个编译器的组件日志和阶段状态。上游 XTerm 历史画面严格比较仍有差异，其失败没有改算为通过。
