# Image paste and negotiated keyboard input

There are two different failure boundaries here: how Nemoterm signals a picture-only paste to an application, and whether a particular client's current input screen accepts it. No pixels are encoded as terminal text.

## Pinned Codex startup under the existing executable

[Hosted run 44361441145](https://github.com/xiongnemo/nemoterm/actions/runs/44361441145), [original four artifacts and hashes](codex-image-timing-fd19411.zip), on executable `fd19411`, SHA-256 `7797b1ae1f5ff7528489db73fee16571c297873c7c7620ad9f73a0614ff71ce4`. For both Ctrl+V and Ctrl+Shift+V, through the window and through the system keyboard, all four trials after the regular composer reported idle submitted exactly one matching 32×16 image. Of the four first-visible-marker gestures, only the system Ctrl+Shift+V trial attached immediately. For the other three, a second user gesture in the same draft after idle submitted one matching image, with no unexpected prior submission or duplicate attachment. The original first-gesture gates are still failed. The client's startup behavior has also been observed on [other Windows console hosts](agent-unicode-boundary.md).

## Wire protocol

[Pre-fix native receipt](image-paste-protocol-before-fd19411.zip) from [44361879422](https://github.com/xiongnemo/nemoterm/actions/runs/44361879422), fixture `a1e498a`, artifact `14455401324` (SHA-256 `396286cbc3ea4a5a700110526ddb009c9f330bc793480b54c73fe37e217119b2`). All eight phases received just `16` hex. That is correct for the three legacy/restored phases and xterm modifyOtherKeys level 1. It is wrong for kitty disambiguate, kitty with event types, kitty all flags, and xterm level 2. Both ends of each action were delimited by a DSR on the same ConPTY stream; the native clipboard and key receiver controls were green. This is a separate, reproducible terminal defect.

The patch routes a generated image-paste key through the active keyboard encoder for the selected terminal. It requests a single logical Ctrl+V. Kitty appends a corresponding key-up only when it was requested; xterm uses its active level and format. Legacy and native Windows consoles retain their original control-character path. The clipboard is released before signalling the application. This does not resend an ignored client shortcut.
