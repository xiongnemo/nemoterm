# Sixel colour commands at a picture boundary

`b5d4514` adds a per-profile option under Window → Rendering → Sixel. By default, each picture starts its own colour command. Enabling the option carries the syntax of a trailing register selector or five-field RGB/HLS definition to the next Sixel DCS of **the same terminal**. A new image has its own pen and resets the numeric accumulator. No palette pointer, surface, or terminal handle crosses the boundary. Switching the setting discards the pending syntax. This comparison does not cover other incomplete expressions or cancelled DCS strings.

The [original hosted XTerm 412 run](https://github.com/xiongnemo/nemoterm/actions/runs/44266405340) uses upstream `5c75ead9a75d4b2e666ca06fa94503b5766ed93f`. Its [original archive](sixel-number-resume-xterm.zip), SHA-256 `ca196cfa9d99d993ce708ccc50dfccbdbb2ddf857cf0c5eba4e494e231459175`, retains the code, executable, input bytes, PNGs and whole/bytewise receipts. For example, a private picture ending in `#2;2;100;0;17`, followed by `100!8~#2!8~` in a new picture, paints eight default-green columns and then eight magenta columns. The old `17` does not prefix the new `100`; the colour write does not select the old register as the new pen. A subsequent private picture can define blue without recolouring either predecessor. The shared-bank control does recolour the earlier shared pixels.

The [product run](https://github.com/xiongnemo/nemoterm/actions/runs/44268562782) compares the actual terminal parser and retained image views against the original XTerm crops and replies. With the option enabled all **56 distinct frames** (8 private-register, 24 across two DCS strings, 24 numeric) match on both input transports with GCC, Clang and MSVC. [Original component observations and artifact hashes](sixel-colour-stream-b5d4514-components.zip). Separate self-tests interleave two live terminal objects and change a profile setting while its next DCS is still being received. The historical default-mode comparisons still record six ReGIS frame differences, and two of eight private-register frames differ from XTerm's cross-picture behavior. Their gates still fail.

The Windows single-image executable was 4,859,392 bytes, SHA-256 `1c7721faac3804855dcd6fc948252b388a8330d4f672e8f566318e41ad3bebd8`. A temporary saved profile enables the option. All six native checks match under actual GDI, actual DirectX and direct observation of the presented GDI client. A fourth requested OpenGL run also passed through **GDI fallback**. [Original Windows receipts and screenshots](sixel-colour-stream-b5d4514-windows.zip) include the source artifact ID, report and capture method for each renderer, and the original digest-checked BMPs. These probes read the stored setting at launch; they did not click or save the checkbox in the settings dialog.
